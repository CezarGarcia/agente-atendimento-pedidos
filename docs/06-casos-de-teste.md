# Casos de teste

Este documento define **o que** precisa ser verdade para a solução estar correta e segura, e
**onde** cada caso é verificado. Ele não depende dos testes automatizados (é o desenho), mas cada
caso aponta para o teste que o implementa.

## Camadas de teste

| Camada                        | O que prova                                                                                                                        | Como roda                                   | Quantidade  |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | ----------- |
| Unitários                     | Regras puras: domínio, confirmação, guardrails, PII, resiliência                                                                   | `npm test` (sem Docker)                     | 230+        |
| Integração                    | API HTTP real + PostgreSQL real (Testcontainers); store do agente em Postgres                                                      | `npm test` (sobe Postgres efêmero)          | 50+         |
| Agente com modelo roteirizado | O harness impõe as regras mesmo com o modelo **errando de propósito**; cada requisição é validada contra as regras da Messages API | `npm test`                                  | 45+         |
| Ponta a ponta (E2E)           | Stack completa via Docker Compose, webhook assinado e navegador; estado conferido na API                                           | `npm run e2e:up && npm run test:e2e`        | 21          |
| Avaliação (evals)             | Comportamento do **modelo real** dentro do harness, com repetição (`pass^k`) e red team                                            | `npm run eval` (requer `ANTHROPIC_API_KEY`) | 31 cenários |

Nos testes automatizados, o modelo e a Fake Store são simulados para resultados previsíveis (como
permite o desafio). Nos E2E, a simulação fica **na fronteira de rede** (stubs HTTP): o código do
agente roda exatamente como em produção.

validada contra as regras estruturais da Messages API (alternância de papéis, posição das

ou ferramentas mudando no meio da conversa).
