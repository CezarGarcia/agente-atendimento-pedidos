# Casos de teste

Este documento define **o que** precisa ser verdade para a solução estar correta e segura, e
**onde** cada caso é verificado. Ele não depende dos testes automatizados (é o desenho). Cada caso
registra objetivo, cenário, condições relevantes e comportamento esperado.

**Cada ID aparece entre colchetes no nome do teste que o verifica**, então um caso pode ser
executado isoladamente:

```bash
npx vitest run -t "AG-17"               # unitários e integração
npm run test:e2e -- -t "E2E-S04"        # ponta a ponta (com a stack no ar)
```

## Camadas de teste

| Camada                        | O que prova                                                                                                                        | Como roda                                                                           | Quantidade  |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ----------- |
| Unitários                     | Regras puras: domínio, confirmação, guardrails, PII, resiliência, configuração                                                     | `npx vitest run --project shared --project orders-api --project agent` (sem Docker) | 563         |
| Agente com modelo roteirizado | O harness impõe as regras mesmo com o modelo **errando de propósito**; cada requisição é validada contra as regras da Messages API | idem                                                                                | 67          |
| Integração                    | API HTTP real + PostgreSQL real (Testcontainers); store do agente em Postgres                                                      | `npm test` roda todas as camadas acima e esta (requer Docker)                       | 74          |
| Ponta a ponta (E2E)           | Stack completa via Docker Compose, webhook assinado e navegador; estado conferido na API                                           | `npm run e2e:up && npm run test:e2e`                                                | 21          |
| Avaliação (evals)             | Comportamento do **modelo real** dentro do harness, com repetição (`pass^k`) e red team                                            | `npm run eval` (requer `ANTHROPIC_API_KEY`)                                         | 89 cenários |

Nos testes automatizados, o modelo e a Fake Store são simulados para resultados previsíveis (como
permite o desafio). Nos E2E, a simulação fica **na fronteira de rede** (stubs HTTP): o código do
agente roda exatamente como em produção.

## Agente: orquestração, confirmação e ferramentas (`apps/agent/src/agent`)

Executados com um **modelo roteirizado** que pode errar de propósito. Toda requisição a ele é
validada contra as regras estruturais da Messages API (alternância de papéis, posição das
mensagens de sistema, `tool_use` sem `tool_result`, conteúdo vazio, histórico alterado, `system`
ou ferramentas mudando no meio da conversa).

## Avaliação com o modelo real (`apps/agent/evals`)

89 cenários com o mesmo formato (objetivo = título; cenário = turnos; condições = persona, falhas e
catálogo adulterado; comportamento esperado = verificações objetivas e, quando há critério, o
juiz). Eles estão em [`evals/scenarios.ts`](../apps/agent/evals/scenarios.ts). As categorias são
`consulta` (5), `cancelamento` (16), `escopo` (11), `falhas` (2) e `red_team` (55). Os cenários
foram criados em quatro levas: os 31 originais; 20 depois da primeira execução com o modelo real
(brechas que a suíte não cobria); 32 de red team avançado (`rta-*`: injeção em vários turnos,
falso resultado de ferramenta, many-shot, paráfrase coagida, homóglifos, canary ofuscado, resumo
envenenado para o atendente, catálogo adulterado, palavra-código e emoji como confirmação, entre
outros); e 6 na rodada 9 (mudar o endereço, "conto" com a frase de sucesso, tradução da frase,
resposta só em JSON com o status pedido, "SIM" adiantado e garantia de entrega). Os relatórios estão em [`evals/`](evals/README.md) e o resumo em
[`08-exemplos-de-conversa.md`](08-exemplos-de-conversa.md).
